# ZUBASH — LP

ZUBASH（OCTBUZZ）の仕様紹介ランディングページ。

- 公開URL: https://octbuzz.github.io/zubash-lp/
- **試遊台の自動ローテーション**: https://octbuzz.github.io/zubash-lp/?kiosk

## ファイル

- `index.html` … Claude Design から書き出した自己展開バンドル1枚。画像168点と
  Webフォントを base64 で内蔵。**直接編集せず `tools/build.py` で生成する**（下記）。
- `pv.mp4` … PV。43秒 / **720×480 (3:2)** / H.264 + AAC 317kbps / 17.6MB。
  元は `Premiere/output/260610_0014_ai_music_1088_4.mp4`。
  moov アトムが先頭にあり（faststart 済み）、頭から順次再生できる。
  **解像度が低い点は把握しておくこと**（下記「動画の解像度」）。
- `pv-poster.jpg` … PV のポスター画像（動画から抜いた実フレーム / 720×480）。
- `tools/build.py`, `tools/kiosk_patch.py`, `tools/char_crop.py` …
  素の書き出しを公開用に変換するスクリプト。
- `.nojekyll` … Jekyll の処理を止めるための空ファイル。消さないこと。
- `og-image.jpg` / `favicon.svg` … OGP・ファビコン用。

## 更新のしかた

Claude Design から書き出し直したら、**上書きせずに** ビルドを通すこと:

```
python3 tools/build.py <素の書き出し.html> index.html
```

素の書き出しに足りないものを `build.py` が当てている。置換元の文字列が
1件見つからなければ assert で止まるので、書き出し側のコードが変わったときに
壊れたまま公開されることはない。**止まったらスクリプトを直すこと。**

当てている内容:

1. **`<title>` / description / OGP。** バンドルは実行時に `document.documentElement`
   をテンプレートごと差し替えるため、外側の `<head>` に入れるだけでは捨てられる
   （タブのタイトルが空になる）。外側と `__bundler/template` 島の中、**両方**に入れる。
2. **PV セクション**をローテーションの1枚目として挿入。
3. **キオスクの動画対応・音声・全画面**（`tools/kiosk_patch.py`）。
4. **キャラクターカードの切り出し位置**（`tools/char_crop.py`）。
   書き出し時点では4体に同じ切り出しが当たっていて、頭の高さも身幅も違うため
   **4体とも頭頂が切れていた**（丸い頭のカエルでいちばん目立つ）。
   正面図の外接矩形を実測して計算し直してある。素材を差し替えたら
   `tools/char_crop.py` の実測値も取り直すこと。

## キオスク（自動ローテーション）— gamescom 試遊台用

URL に `?kiosk`（`?kiosk=1` / `?kiosk=true` も可）を付けると全画面ローテーションに入る。

**PV(43秒) → ヒーロー → 01〜06 の8枚**を回し、最後まで行くと PV に戻る。
1周およそ 2分49秒。PV 以外は1枚18秒（`kioskSeconds` プロパティ、URLからは変えられない）。

- **フッターはローテーションに入れていない**（中身が実質無く、18秒の空白になるため）。
  スクロール表示のページ下部にはそのまま残る。
- PV フレームだけは18秒ではなく**動画の尺**で送る。動画の `ended` でも次へ送るので、
  尺の誤差で止まらない。**動画が読み込めない・尺が取れないときは18秒に落ちて
  ローテーションは回り続ける**（無人運用で止めないため）。

| 操作 | 動作 |
|---|---|
| ← → | 前／次へ |
| クリック | 次へ |
| Space | 一時停止・再開（動画も止まる。停止中は進捗バーがピンク） |
| **M** | 音声のオン／オフ |
| F | 全画面表示に入る／出る |
| Esc | 全画面中なら全画面だけ解除。全画面でなければキオスクを抜ける |

### 音声（ここが運用上いちばん重要）

**ブラウザの自動再生ポリシーにより、ユーザー操作が1回もない状態では音を出せない。**
そのため **ミュートで再生を開始し、最初のクリックまたはキー入力で自動的に音を入れる**。
展示では全画面にするために F を押す（またはボタンを押す）ので、その操作が
そのまま音声解除になる。

ミュート中は右下のボタンが **`SOUND OFF — PRESS M`** とライムグリーンで強調される。
**設営時はこれが `SOUND ON (M)` になっているか必ず確認すること。**

### そのほかの注意

- 起動時に自動で全画面へは入らない。Fullscreen API もユーザー操作を必須としており、
  `?kiosk` で直接開いた時点では必ず拒否されるため。**F かボタンを1回押す。**
- ブラウザがバックグラウンドタブになると動画の再生が止まる（ブラウザの仕様）。
  試遊台では前面・全画面で使うこと。
- iOS Safari など要素の全画面表示に対応しない環境では全画面ボタンを出さない。
- dc のテンプレートコンパイラは値なしの `controls` 属性を落とす（`playsinline` は残るのに）。
  そのため通常表示の操作UIは `componentDidMount` で JS から付け直している。
- キオスクを抜けるときに `keydown` / `resize` / `pointerdown` / `fullscreenchange` の
  購読を解除している。解除しないと通常表示に戻ったあとも Space が `preventDefault` され、
  スペースキーでページをスクロールできなくなる。

## 動画の解像度

現在の `pv.mp4` は **720×480**。同じ PV の HD 版（`Premiere/output/hd_1.mp4`、
2160×1440 / 41MB）もあるが、ファイルサイズを優先して低解像度版を採用している。

**試遊台の大きい画面で全画面表示すると、相応に眠い絵になる。**
1920×1080 のモニタなら約2.7倍（面積で約7倍）の拡大になる。
会場のネットワークが不安な場合は軽い方が有利だが、画質を取るなら
`hd_1.mp4` に差し替えること（3:2 で同じなので `pv.mp4` を置き換えるだけでよい。
HTML 側の変更は不要。ポスターも HD 版から取り直すこと）。

中間の解像度（1280×854 程度）を作るなら ffmpeg が要る:

```
brew install ffmpeg
ffmpeg -i hd_1.mp4 -vf scale=1280:-2 -c:v libx264 -crf 23 -preset slow \
       -c:a aac -b:a 192k -movflags +faststart pv.mp4
```

なお音声は低解像度版の方が良い（317kbps / HD 版は 93kbps）。

## 帯域について

GitHub Pages は1ファイル100MBまでなので余裕はあるが、帯域のソフト上限が
月100GB ある。通常表示では `preload="metadata"` なので、再生しない訪問者には
動画本体が転送されない。試遊台のローテーションでは毎周ダウンロードし直すのではなく
HTTP キャッシュ（ETag）が効く。
